Extend the router in `microweb/routing.py` with typed path parameters, proper method handling, reverse routing and conflict detection:

1. Path parameters: a segment `<name>` or `<conv:name>` captures one path segment. Converters are `str` (the default: any non-empty segment), `int` (ASCII digits only, `[0-9]+`, converted to `int`) and `path` (allowed only as the last segment; captures the remaining one or more segments joined with `/`). Captured values come from the decoded segments returned by `urls.split_path`, and `Router.match(...).params` holds the converted values.
2. Invalid patterns: an unknown converter (e.g. `<float:x>`), a `path` converter that is not the last segment, or a parameter name used twice in one pattern makes `add_route` raise `RouteError`, a new exception in `routing.py` that subclasses `ValueError`.
3. Precedence: when several routes match the path and allow the method, the most specific one wins, comparing segments from the left: a static segment beats `int`, which beats `str`, which beats `path`. Registration order does not matter.
4. Methods: method names are case-insensitive and a route that allows `GET` also answers `HEAD`. If at least one route matches the path but none allows the method, `match` raises `http.MethodNotAllowed` whose `allowed` lists every method (including the implicit `HEAD`) of all routes matching the path; if no route matches the path at all, it raises `http.NotFound`.
5. Reverse routing: `Router.url_for(name, **params)` builds the path of the route registered with that `name`. Values are converted with `str()` and percent-encoded with `urls.quote_segment` (for a `path` parameter each `/`-separated part is encoded separately and the `/` is kept). Keyword arguments that are not path parameters are appended as `?` followed by `urls.build_query(...)` of them. An unknown name, a missing parameter, or an `int` parameter whose value is neither a non-negative `int` nor a digit string raises `BuildError`, a new exception in `routing.py` that subclasses `LookupError`.
6. Conflicts: `add_route` raises `RouteConflict` (a subclass of `RouteError`) when an already registered route has an equivalent pattern (after `urls.normalize_path`, the same static segments and the same converters in the same positions, whatever the parameter names) and shares at least one method with the new route, or when the new route's `name` (if not `None`) is already taken. The same pattern with disjoint methods is allowed.

Add tests for the new behaviour in `tests/test_routing.py`. Keep the change focused on this feature.
